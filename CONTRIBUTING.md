# Contributing

openthaiknowledge grows by people lending their AI agents' time: pick a task,
let your agent do the work under this repository's rules, review what it
produced, and open a pull request. CI checks the mechanical rules; a
maintainer reviews the rest.

> Code is licensed Apache-2.0 and content CC BY 4.0 (README → License); your
> contribution is too.

## 1. Pick a task

Open tasks are GitHub issues labelled `task: indicator` (a curriculum
indicator no set practises yet) or `task: digest` (a source file not yet
turned into sets). Comment on the issue to claim it, so two people do not do
the same work. The list is generated by `python scripts/task_queue.py`.

You can also propose your own: a topic that deserves more practice, or a
source you are allowed to use. Open an issue first.

**Digesting an exam paper of your own** (one you wrote, or may publish): put the
PDF in `openthaiknowledge-bank/contrib/<your GitHub name>/` (git ignores that folder, so
the PDF is never committed) and ask your agent to use the `sheet-to-generator`
skill. Its "Your own paper" section has the steps. The paper's question text is
published with the generators, so the rights must be yours to give.

## 2. Set up

The quickest way is the set-up prompt in the [README](README.md#contribute-with-your-ai-agent):
paste it into your agent and it forks, clones, installs and checks
everything. By hand:

```bash
gh repo fork KananatSSN/openthaiknowledge --clone --default-branch-only
cd openthaiknowledge
uv venv --python 3.12 && uv pip install --python .venv -e ".[test]" ruff
```

On Windows, set `PYTHONUTF8=1` (for example `setx PYTHONUTF8 1`, then open a
new terminal) so Python can print Thai.

Run your agent (Claude Code, Codex, or any agent that reads `AGENTS.md`)
from the repository root. It finds the rules in `AGENTS.md` and the
procedures in `.agents/skills/`.

## 3. What a good contribution looks like

- **Answers are right, provably.** Each answer is computed by a solver and
  checked by an independent route in the set's tests. Read a few draws
  yourself before you open the pull request, e.g.
  `python -c "from random import Random; from otk.api import REGISTRY; print(REGISTRY['KEY'].generate(Random(1)))"`.
- **Wrong choices are real mistakes.** Each distractor is what a learner gets
  by a specific error, named with `named(...)` where the mistake has a name.
- **Thai is natural** and matches the curriculum's terms for the level.
- **Provenance is honest.** `Provenance("original")` for your own questions;
  `Provenance("adapted", sources=(...))` citing every question you adapted.
  Do not copy copyrighted text beyond what the set needs.
- **Small.** One topic, indicator or source per pull request.

## 4. Open the pull request

- Every commit is signed off (`git commit -s`), certifying the
  [Developer Certificate of Origin](https://developercertificate.org/): you
  have the right to submit the work. CI checks for the `Signed-off-by` line.
- Fill in the template: what the sets practise, which task it closes, which
  agent and model did the work, and what you checked yourself.
- CI must be green: the full suite, including the golden draws, provenance
  and code-safety checks.

## What review looks for

The maintainer checks the maths, the Thai, the distractors, and anything CI
cannot judge: whether an adapted source may be used, and any
`# otk: allow` exception (only maintainers add those). Changes to
`otk/api.py`, the safety check, or another set's draws need the maintainer's
agreement before you start.
